# Message 组件实现原理及其相关

本文档对应同目录下的 `index.vue`，用于说明 Message 组件的职责、数据流、动画时间线、SVG 滤镜实现方式、对外 API 和维护注意点。

## 组件定位

`Message` 是一个全局顶部消息气泡组件。它通过 `Teleport` 挂载到 `body`，避免受到父组件的 `overflow`、`transform`、`z-index` 等样式影响。

每条消息的完整生命周期为：

1. 入场：标签从上方落到目标位置。
2. 滤镜收束：SVG blob 滤镜从粘连模糊过渡到等效无滤镜。
3. 文字跳动：内容逐字跳动一次，不循环。
4. 停留：入场结束后开始按 `duration` / `d` 计时。
5. 退场：标签向上移动并透明。
6. 清理：通过 `addMessage` 创建的本地消息在动画结束后自动移除。

## 对外参数

组件 props：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `text` | `string` | 默认消息内容。当没有传 `items` 且没有调用过 `addMessage` 时，会用它生成一条默认消息。 |
| `items` | `MessageOptions[]` | 外部受控消息列表，适合父组件自己管理消息数据。 |
| `autoplay` | `boolean` | 是否自动播放 timeline。为 `false` 时 timeline 会创建但暂停，可通过 `play()` 手动播放。 |

单条消息配置 `MessageOptions`：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string \| number` | 消息 id。不传时按来源和索引自动生成。 |
| `text` | `string` | 消息文本。 |
| `content` | `string` | 消息文本，优先级高于 `text`。 |
| `x` | `string` | 标签横向位置，直接写入 CSS 变量 `--x`。 |
| `y` | `string` | 标签纵向位置，直接写入 CSS 变量 `--y`。 |
| `s` | `string` | 标签基准尺寸，直接写入 CSS 变量 `--s`。 |
| `color` | `string` | 气泡背景色。 |
| `duration` | `string \| number` | 入场结束后的停留时长，单位为秒；也支持 `'500ms'`。 |
| `d` | `string \| number` | `duration` 的简写；如果同时存在，`duration` 优先。 |
| `delay` | `string \| number` | 整条消息 timeline 开始前的延迟，仅 `autoplay=true` 时直接生效。 |

## 对外方法

组件通过 `defineExpose` 暴露以下方法：

| 方法 | 说明 |
| --- | --- |
| `addMessage(message)` | 追加一条本地消息，返回生成后的 id。字符串会被转换成 `{ content: message }`。 |
| `removeMessage(id)` | 主动移除一条本地消息，并停止对应 timeline。 |
| `clearMessages()` | 清空本地消息和所有动画缓存。不会直接修改父组件传入的 `props.items`。 |
| `play()` | 播放全部已创建 timeline。 |
| `pause()` | 暂停全部已创建 timeline。 |

示例：

```vue
<script setup lang="ts">
import { ref } from 'vue';
import Message from './views/message/index.vue';

const messageRef = ref<InstanceType<typeof Message> | null>(null);

const showMessage = () => {
    messageRef.value?.addMessage({
        content: '保存成功',
        color: '#22c55e',
        duration: '2s',
        x: '50%',
        y: '60px',
        s: '50px',
    });
};
</script>

<template>
    <Message ref="messageRef" />
    <button @click="showMessage">show</button>
</template>
```

## 数据流

组件内部的数据流如下：

```text
props.items / addMessage()
        ↓
MessageOptions
        ↓ normalizeMessage()
RuntimeMessage
        ↓ computed messageList
v-for 渲染 DOM 与 SVG filter
        ↓ setMessageRef()
messageElementMap
        ↓ syncMessageAnimations()
runMessageAnimation()
        ↓
GSAP timeline 播放完整生命周期
```

### 消息来源

`RuntimeMessage.source` 有三种：

| source | 来源 | 生命周期 |
| --- | --- | --- |
| `default` | 没有 `items` 且没有本地消息时，用 `props.text` 创建的默认预览消息 | 播放完成后保留数据，不自动删除 |
| `prop` | 父组件传入的 `props.items` | 数据归父组件管理，组件不会主动删除 |
| `local` | 调用 `addMessage()` 追加的消息 | 播放完成后自动从 `localMessageList` 删除 |

这样区分是为了避免组件误删父组件数据，同时让命令式添加的临时消息可以自动清理。

## 消息归一化

`normalizeMessage()` 将外部传入的 `MessageOptions` 转换成内部统一的 `RuntimeMessage`。

它主要处理：

- 自动生成稳定字符串 `id`
- 为每条消息生成独立 `filterId`
- 选择展示内容：`content ?? text ?? props.text`
- 填充默认位置、尺寸和颜色
- 将 `duration` / `d` / `delay` 统一转换为秒
- 标记消息来源 `default` / `prop` / `local`

归一化后，模板和动画代码只处理完整数据，不需要到处判断字段是否存在。

## DOM 结构

模板主要分三层：

```html
<div class="message">
    <div class="message-body">
        <span class="message-content">
            <span class="message-char">字</span>
        </span>
    </div>
</div>
```

职责划分：

| 节点 | 职责 |
| --- | --- |
| `.message` | 外层滤镜容器，负责 `filter: url(#filterId)`。 |
| `.message-body` | 真正的气泡标签，负责入场、退场、透明度动画。 |
| `.message-content` | 字符容器，维持一行布局。 |
| `.message-char` | 单个字符，负责逐字跳动动画。 |

隐藏的 `svg` 中还会为每条消息渲染一组独立 filter：

```html
<filter id="...">
    <feGaussianBlur />
    <feColorMatrix />
</filter>
```

每条消息必须使用独立 filter，因为 GSAP 会逐帧修改 `stdDeviation` 和 `values`。如果多个消息共用同一组 filter，它们的滤镜状态会互相覆盖。

## 函数式 ref

模板中使用：

```vue
:ref="setMessageRef(message.id)"
```

原因是每条消息都需要拿到真实 DOM，供 GSAP 查询 `.message-body` 和 `.message-char`。

Vue 的函数式 ref 类型允许传入：

- `Element`
- `ComponentPublicInstance`
- `null`

所以 `setMessageRef` 的参数不能只写成 `Element | null`。当前实现会先判断：

```ts
if (element instanceof HTMLElement) {
    messageElementMap.set(id, element);
}
```

只有真实 `HTMLElement` 才会进入动画缓存。

## 动画时间线

每条消息由 `runMessageAnimation()` 创建一条独立 GSAP timeline。

时间线结构：

```text
t = delay
    set message filter 为 url(#filterId)
    set body 到入场起点
    set 字符初始状态

t = 0 → introDuration
    body y: introStartY → 0

t = 0.5 → 1.4
    SVG filter 参数收束到 identity

t = introDuration
    字符逐字跳动一次

t = introDuration + message.duration
    body 向上移动并 opacity: 0

complete
    如果是 local 消息，从 localMessageList 删除
```

其中：

```ts
const introStartY = -Math.max(bodyElement.offsetHeight * 1.6, 64);
const exitY = -Math.max(bodyElement.offsetHeight * 0.8, 24);
```

入场起点和退场距离基于标签真实高度计算。这样当字号或 padding 变化时，动画距离也会跟着变化。

## 停留时间规则

停留时间从“入场结束后”开始算，不是从组件挂载或 timeline 开始算。

退场开始时间为：

```ts
introDuration + message.duration
```

例如：

- `introDuration = 1.5`
- `message.duration = 2`

则：

```text
0s      开始入场
1.5s    入场结束，开始计算停留时间
3.5s    停留结束，开始退场
```

## SVG 滤镜原理

组件的 blob 效果由两个 SVG filter 节点组合：

```html
<feGaussianBlur in="SourceGraphic" stdDeviation="10" result="blur" />
<feColorMatrix in="blur" mode="matrix" values="..." />
```

`feGaussianBlur` 负责模糊边缘，`feColorMatrix` 通过 alpha 通道增强透明度对比，制造粘连、融合的视觉效果。

初始矩阵最后一行为：

```text
0 0 0 20 -9
```

含义是增强 alpha：

- `alpha = 20`
- `offset = -9`

动画结束时过渡到：

```text
0 0 0 1 0
```

这表示 alpha 不再被额外增强，视觉上接近普通元素。

## 为什么不用 CSS 直接过渡到 `filter: none`

`filter: url(#id)` 到 `filter: none` 不是连续可插值的滤镜参数。浏览器通常只能在某个时间点直接切换，因此会出现“滤镜突然消失”的跳变。

当前做法是：

1. 始终保持 `filter: url(#filterId)`。
2. 用 GSAP 动态修改 SVG 内部参数：
   - `blur: 10 → 0`
   - `alpha: 20 → 1`
   - `offset: -9 → 0`
3. 当 SVG filter 已经等效无滤镜后，再执行 `filter: none`。

这样最后一步切换不会造成明显视觉跳变。

## 文字跳动原理

文字会被拆成字符数组：

```ts
Array.from(content)
```

模板中每个字符都会渲染为：

```html
<span class="message-char">字</span>
```

每个字符设置为 `inline-block`，这样 GSAP 才能独立写入 `transform`。

跳动动画：

```ts
keyframes: [
    { y: -8, rotation: 5, duration: 0.35, ease: 'power2.out' },
    { y: 0, rotation: 0, duration: 0.35, ease: 'power2.inOut' },
]
```

`stagger.each = 0.08` 表示字符依次延迟 `0.08s` 播放，形成波浪跳动效果。

## 缓存与清理

组件维护三个 Map：

| 名称 | 作用 |
| --- | --- |
| `messageElementMap` | 保存每条消息对应的真实 DOM。 |
| `messageTimelines` | 保存每条消息的 GSAP timeline，用于暂停、继续、删除。 |
| `activeMessageKeys` | 保存动画输入快照，用于判断是否需要重建 timeline。 |

清理场景：

- 消息从 `messageList` 消失时，清理对应 timeline 和 DOM 引用。
- `removeMessage(id)` 被调用时，清理对应本地消息。
- 组件卸载时，`clearMessages()` 会杀掉全部 timeline，并清空缓存。

这样可以避免 GSAP 动画在组件卸载后继续持有 DOM。

## 样式设计要点

### Teleport 浮层

`.message-container` 固定在视口顶部：

```scss
position: fixed;
top: -2rem;
z-index: 9999;
pointer-events: none;
```

`pointer-events: none` 表示消息只展示动画，不拦截页面点击。

### 水平定位

`.message-body` 的 `left` 来自 `--x`，水平居中通过 GSAP 的 `xPercent: -50` 完成。

这里不在 CSS 中写 `transform: translateX(-50%)`，因为 GSAP 后续还要写 `y` 动画。如果 CSS 和 GSAP 同时写 transform，容易互相覆盖。

### 默认隐藏

`.message-body` 初始 `opacity: 0`，等待 timeline 初始化到入场起点后再显示，避免首帧闪烁。

## 维护注意事项

1. 如果新增影响动画的字段，需要同步加入 `getMessageAnimationKey()`，否则字段变化时 timeline 不会重建。
2. 如果要支持多行文本，需要重新评估 `.message-content` 的 `inline-flex` 和 `.message-char` 的布局。
3. 如果改变 `filterState` 的初始参数，需要同时确认 `getMatrixValues()` 的 identity 终态仍为 `alpha=1, offset=0`。
4. 如果要让 `props.items` 中的消息播放结束后消失，应由父组件移除对应 item，不建议子组件直接修改 props 数据。
5. 如果新增多个 Message 实例，`componentId` 会避免 filter id 冲突，不要改成固定 id。

## 常见问题

### 为什么本地消息结束后会自动删除？

本地消息来自 `addMessage()`，通常是 toast 式临时消息。播放完成后自动删除可以避免列表持续增长。

### 为什么 props.items 不自动删除？

`props.items` 属于父组件数据。子组件不能也不应该直接修改父组件数组，否则数据流会变得不可预测。

### 为什么要等 `nextTick()`？

`messageList` 变化后，Vue 需要先把新的 DOM 渲染出来。GSAP 只能操作真实 DOM，所以 `syncMessageAnimations()` 会先等待 `nextTick()`。

### 为什么要用函数式 ref，而不是只通过 querySelector？

函数式 ref 可以按消息 id 精确维护 DOM 映射，删除和重建动画时更可靠。`querySelector` 仍用于在单条消息内部查找 `.message-body` 和 `.message-char`。

### 为什么要用 `Array.from(content)` 拆字符？

`Array.from` 对部分 Unicode 字符的处理比 `split('')` 更稳，适合当前默认文本中包含表情符号和特殊字符的场景。
